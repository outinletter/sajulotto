# 앱 기획안 — 4.3(b) 재심사 대응

## 1. 포지셔닝 (가장 중요)
Apple이 거절한 이유는 "운세·점술 앱이 이미 충분하다"는 것이다. 운세 리포트를 읽는 앱이 아니라 **매일 쓰는 개인 선택 도구**로 정의를 바꾼다.

- 한 줄: 내 사주를 시드로 삼아 오늘의 숫자와 선택을 고르고, 그 결과를 기록·회고하는 개인 의사결정 도구
- 카테고리 제안: 라이프스타일 (엔터테인먼트·운세 키워드는 메타데이터에서 최소화)
- 앱 이름·키워드에서 '천기누설', '운세', '점', '사주팔자 풀이'를 빼고 '선택', '번호', '오늘'을 앞세운다.
- 사주는 입력 데이터이자 계산 시드로 쓰고, 긴 해석 글은 보조 정보로 낮춘다.

## 2. 핵심 기능
### A. 사주 로또 번호 생성기
- 출생 연월일시를 한 번만 입력해 기기에 저장한다 (시간 미상 허용).
- 매주 회차별 번호 5세트를 만든다. 입력은 `내 사주 + 회차 + 사용자 시드`이고 같은 입력이면 항상 같은 결과가 나온다(결정론).
- **번호마다 선정 근거**를 보여준다. 예: "목(木) 보강 → 3·8, 오늘 일진 합 → 17".
- 고정수·제외수 지정, 번호 재생성 횟수 제한(회차당 N회)을 둔다.
- 당첨 확률을 높인다는 표현은 쓰지 않는다. 오락용이며 모든 조합의 확률은 같다고 화면에 명시한다.

### B. 오늘의 선택 (의사결정)
- 후보 2~8개를 입력한다 (점심 메뉴, 약속 장소, 할 일 순서 등).
- 오늘 일진과 내 오행 균형을 바탕으로 후보를 순위화하고 이유를 한 줄로 설명한다.
- 메뉴 프리셋은 한식·중식·양식·일식·카페 등을 오행에 매핑한다(수·화·목·금·토). 직접 입력도 가능하다.
- 룰렛 연출과 햅틱, '다시 뽑기'는 하루 1회만 허용해 선택 피로를 줄인다.
- 결과를 저장하고 하루 뒤 "그 선택, 어땠나요?"(좋음/보통/별로)를 묻는다.

### C. 기록과 회고 (차별점)
- 모든 번호·선택을 기기 안에 기록한다.
- 선택 만족도를 오행·요일별로 집계해 "나는 화(火)가 강한 날 결정을 잘 내린다" 같은 개인 통계를 보여준다.
- 로또 회차 결과를 직접 입력하면 실제 일치 개수를 기록하고, 누적 지출·일치 통계를 정직하게 보여준다.
- 월 지출 한도를 설정하면 초과 시 경고한다 (책임 있는 이용).

| 높음 | 홈·잠금화면 위젯 | 오늘의 오행, 이번 주 번호 1세트, 오늘의 선택 | WidgetKit |

## 4. 심사 대응
- **차별점 서술**: 심사 노트에 "운세 읽기 앱이 아니라, 결정론적 엔진으로 번호와 선택을 만들고 회고 통계를 보여주는 개인 도구"라고 적는다. 위젯, App Intents, 개인 회고 통계, 지출 한도를 증거로 든다.
- **화면 전략**: 스크린샷은 운세 풀이 화면이 아니라 선택 룰렛, 번호 근거, 회고 통계, 위젯을 보여준다.
- **무료·무계정·오프라인**: 기본 기능은 네트워크 없이 동작한다. AI 해석은 선택 사항으로 두거나, 이번 심사에서는 제외해 변수를 줄인다.
- **도박 오해 방지**: 구매 연결, 당첨 보장 표현, 배팅 유도를 두지 않고 지출 한도 기능을 노출한다.
- **회신 방식**: Apple 메시지에 앱을 이렇게 재정의했다고 답하고, 새 화면 녹화를 첨부한다. 이의제기(App Review Board)도 병행할 수 있다.
- **위험**: 이 방향이 4.3(b) 통과를 보장하지는 않는다. Apple은 신규 앱 제출을 권고했다. 기능을 바꿔도 같은 사주 앱으로 보이면 다시 거절될 수 있으므로, 사주 풀이 비중을 줄이고 선택·회고 중심으로 실제로 바꾸는 것이 전제다.
